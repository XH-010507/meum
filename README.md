# 家庭小厨房 · meum

基于 [fightforbelief/family-menu-miniprogram](https://github.com/fightforbelief/family-menu-miniprogram) 的 MIT 开源适配版。保留上游原生微信小程序页面和样式，支持中文家庭内部点菜，无支付，无需自建服务器。原始许可见 [LICENSE](LICENSE)，来源版本与修改范围见 [UPSTREAM.md](UPSTREAM.md)。

本版已加入**单张图片严格小于5MB**、家庭成员/管理员云端权限、失败保留旧图片与点菜篮。此项目需要你自己的微信小程序 AppID 和微信云开发环境才能使用共享业务；没有配置时会明确提示，不会伪造提交成功。

## 已有功能

- 按菜系、分类浏览菜品，查看图片、介绍和食材。
- 点菜篮增减份数，选择用餐日期/时间，填写称呼和口味备注，提交点菜。
- 家人查看自己的点菜记录，管理员查看家庭记录及备菜清单。
- 管理员新增、编辑、上下架菜品，选择、替换、移除、预览图片。
- 备菜清单汇总食材涉及的菜品与份数，可复制到剪贴板。原数据未提供重量，页面不会编造克数。
- 保留上游可选的254道种子菜品，默认图随代码携带，无需另上传默认图。

## 另一台电脑首次使用

1. 在装有微信开发者工具的那台电脑上，用 GitHub Desktop 登录你的账号，选择 `File → Clone repository → URL`，填 `https://github.com/XH-010507/meum.git`，选一个固定文件夹。**只需要克隆这一次**。也可以首次下载 ZIP，但 ZIP 文件夹不能直接拉取后续更新，建议用克隆方式。
2. Windows 双击项目根目录的 `首次配置.cmd`。它只在文件缺失时复制配置模板，不会覆盖已有配置；不需要安装 Node.js。Mac/Linux 可手动复制 `project.config.example.json` 为 `project.config.json`，复制 `miniprogram/config/local.example.js` 为同目录 `local.js`。也可安装 Node.js 后执行 `npm run setup`。
3. 微信开发者工具导入这个固定文件夹，在导入界面填写**你自己的 AppID**。不填写 AppSecret；项目不包含任何人的 AppID/环境ID。AppID可保存在本机 `project.config.json`。
4. 打开本机 `miniprogram/config/local.js`，填写自己的云环境ID，例如保留 `module.exports = { envId: '' };` 的结构，只把空字符串替换成实际ID。此文件和 `project.config.json` 均已被Git忽略，不会推送到公开仓库，也不会被日后更新覆盖。
5. 按下节完成一次云环境和成员配置，然后点击“编译”。仅家庭内部使用可按微信后台要求添加开发/体验成员并用预览或体验版，无须为本项目启用支付或发布正式版。云开发资源的开通条件及计费以你的控制台为准。

## 一次性云环境配置

这是新引入的开源项目，集合结构与此前 family-menu-v1 ZIP 不同。**请先保留旧项目及旧数据，用新的云环境验收本版；不要向旧集合直接导入种子数据，也不要删除旧环境。** 本版不自动迁移旧数据。

1. 创建这六个集合，注意是单数 `cuisine` 和 `order`：
   - `cuisine`：菜系。
   - `cuisine_category`：分类。
   - `dish`：菜品。
   - `order`：点菜记录。
   - `family_config`：家庭管理员和成员。
   - `images`：已校验图片及短期上传分段。
2. 六个集合的客户端安全规则均使用 `database_init/deny-client-rules.json`，即 `{"read":false,"write":false}`。云存储也拒绝客户端直接读写。所有业务由鉴权后的云函数执行；图片由云函数签发临时访问链接。不要使用“所有用户可读写”。
3. 可选：把 `database_init/cuisine.json` 导入 `cuisine`，`cuisine_category.json` 导入 `cuisine_category`，`dish.json` 导入 `dish`。这些文件是微信导入使用的“一行一条JSON记录”，不是一个JSON数组。只在新环境导入一次，以免重复。可以只导入菜系/分类，然后自行添加家庭菜谱。
4. 将 `cloudfunctions/` 下15个云函数完整上传并部署，选择“云端安装依赖”；每个文件夹都包含独立所需文件，包括 `guard.js`。建议函数超时60秒，运行时选择控制台支持的 Node.js 版本。依赖沿用上游 `wx-server-sdk`，不需要自建后端服务器。
5. 在首页点击“查看本人身份码”，私下保存你的 OPENID。该接口只返回调用者自己的身份，不会自动授予管理员权限。
6. 在云控制台向 `family_config` 添加 `_id` 为 `main` 的文档：`admins` 为管理员真实 OPENID 字符串数组，`members` 为其他家人真实 OPENID 字符串数组。参考 `family_config.example.json`，空数组默认拒绝业务。此配置只放云控制台，不提交到GitHub。
7. 管理员点击“大厨专属按钮”即可进入管理；其他家人先获得微信体验成员资格，再将其身份码加入家庭 `members`。这两层权限都需要配置。未加入家庭的账号不能读取或写入业务；家人只能查看自己的记录，管理员可看全家庭记录。
8. 若订单查询提示创建索引，按控制台提示为 `order` 的 `owner + createTime` 等查询创建索引。代码每批100条查询，家庭菜谱最多读取1000道，记录最多读取最近500条，本版不适合商业餐厅。

## 以后怎么更新：不用再解压覆盖文件

1. 我把修改提交到这个仓库。
2. 你在另一台电脑的 GitHub Desktop 打开 `meum`，点击 `Fetch origin`，有更新时点击 `Pull origin`。
3. 微信开发者工具仍打开原来那个固定文件夹，点击“编译”即可，**不需要重新导入项目**。
4. 如果修改包含云函数，再上传部署改动的云函数；只有界面修改时无需重新部署云函数。本机 AppID/环境ID不随拉取改变。

如果你同时在那台电脑改过相同代码，Git可能提示冲突，此时保留现场，不要强行覆盖。源码同步不会复制云数据库，也不会清空家庭记录。

## 图片上限和验证

- 本项目5MB按 `5 × 1024 × 1024 = 5,242,880` 字节计算；最大允许5,242,879字节。**等于或超过5,242,880字节一律拒绝**。JPEG/PNG；不自动压缩，保留原图质量。用户可以自行压缩后重新选择。
- 选择器返回时、读取本地文件信息时、读取实际文件内容后分别检查大小。无法确认大小则拒绝。超限有中文弹窗，且不会开始云端上传，也不会替换旧图。
- 为避免接近5MB图片经Base64编码后使请求过大，客户端以192KiB小段发往 `uploadImage` 云函数。云端每次校验管理员身份、会话所有者和分段长度，完整合并后再次校验实际字节数及JPEG/PNG文件头；通过后才保存图片并登记供菜品引用。文件头检查不等于完整恶意文件扫描。
- 云端会话30分钟过期，暂存于 `images` 集合，正常完成/取消尽力清理。关闭小程序或断网可留下暂存；可在控制台按 `kind` 为 `imageUpload` / `imageUploadChunk` 且 `expiresAt` 早于当前时间超过24小时清理。不要删除正常含 `fileId` 的登记记录。
- 替换/移除图片仅改变引用，不自动删旧文件。取消编辑、请求响应丢失或重复完成请求可能留下未引用图片；管理员备份数据后核对 `dish.image` 与 `images.fileId`，再清理确认无人引用的旧文件。不会自动删除用户数据。

### 手动测试

1. 管理员新增菜品，选择一个600KB或4MB JPEG/PNG，应正常预览、保存，其他家人可以看到图片。
2. 准备精确大小为5,242,879、5,242,880、5,242,881字节的图片，分别应为“成功、拒绝、拒绝”。安装 Node.js 后运行 `node tests/image-fixtures.js` 可生成这三张有效PNG到 `tests/fixtures/`。以本地文件字节数为准，系统显示的“5.0MB”可能四舍五入；相册重编码可能改变样图大小，精确边界用开发者工具选本地文件测试。
3. 已有图的菜品换超限图、取消选图、断网上传，应保留旧图。再选择小图成功后保存，检查列表、详情、点菜篮和图片预览。可移除图片恢复默认图。
4. 断网提交订单：不应提示“提交成功”，点菜篮保留；恢复网络保持内容不变重试，不应产生重复记录。管理员查看记录与备菜清单；普通家人不能修改菜谱、上传图片、删除订单或读取别人记录。
5. 用两个微信身份和两台设备在自己的测试云环境验收。尚未替你执行实际微信开发者工具编译、云部署或真机测试。

## 自动验证与维护

安装 Node.js 后，在根目录执行 `npm test`，无需第三方测试依赖、无需云账号。结果写入 `TEST-RESULTS.txt`，覆盖图片精确边界/分段重组、身份权限、订单隔离/重试、断网保存、选图失败保留旧图，以及JS/JSON/WXML静态检查。

如修改统一后端权限逻辑 `server/guard.js`，先执行 `npm run sync-cloud`，再测试并部署受影响云函数。仓库已包含同步后的副本，普通使用无需额外生成或构建。

主要适配文件：`miniprogram/utils/image.js`、`miniprogram/utils/api.js`、菜品编辑与点菜确认页、`cloudfunctions/uploadImage/`、`server/guard.js`、身份验证云函数、订单/备菜函数，以及本机配置模板、测试和本文档。源码来源与上游提交号见 `UPSTREAM.md`。
